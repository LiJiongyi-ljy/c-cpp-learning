- C 常见形式：gcc hello.c -o hello.exe，然后 .\hello.exe

【四、已经理解的 Hello World】
示例：
#include <stdio.h>

int main(void) {
    printf("Hello C from MSYS2 UCRT64 + VSCode\n");
    return 0;
}

已经理解：
1. #include <stdio.h>
   - 引入标准输入输出相关声明。
   - printf 的使用需要相关声明。

2. int main(void)
   - int：main 函数返回 int。
   - main：程序入口函数。
   - (void)：main 不接受参数。
   - 现代 C 中推荐写 int main(void)，因为它明确表示没有参数。
   - int main() 在传统 C 语境下表示参数列表未指定，不完全等同于 int main(void)。

3. printf(...)
   - 输出文本。
   - \n 表示换行。

4. return 0;
   - 结束当前函数。
   - 返回整数 0。
   - 对 main 来说，这个返回值会成为程序的退出状态。

【五、已经理解的 void】
已经理解 void 的核心直觉：
- void 可以先理解为“没有值 / 没有具体值”，具体含义取决于上下文。

例子：
void hello(void)
{
    printf("Hello\n");
}

这里：
- 第一个 void：函数不返回一个具体值。
- 第二个 void：函数不接受参数。

Python 对比：
Python：
def hello():
    print("Hello")

C：
void hello(void)
{
    printf("Hello\n");
}

【六、已经理解的 return 0 / return 1】
已经明确：
- return 0; 和 return 1; 都是“返回一个整数并结束当前函数”。
- 对 main 来说，返回值会成为程序的 exit status（退出状态）。

重要结论：
- 0 通常按约定表示成功。
- 非 0 通常表示错误、失败或其他特殊状态。
- 1 并不是 C 语言规定的“固定错误码”。
- 可以由程序自己定义不同的非零状态，例如：
  0 = success
  1 = file missing
  2 = cannot open file
  3 = invalid input
  4 = network error
- 因此不要记成“C 规定 0=正常、1=异常”。
- 更准确的说法是：return 0 返回整数 0；对于 main，这通常被环境按成功状态处理。非零值通常用于表示错误或特殊情况。
- C 标准库还提供 EXIT_SUCCESS 和 EXIT_FAILURE（来自 <stdlib.h>），但初学阶段 return 0; 已经足够。

【七、已经开始学习：变量和数据类型】

为什么 Python 可以写：

原因：
C 更强调变量的明确类型。

Python：

当前形成的直觉：
- C 中变量通常需要明确声明类型。
- Python 通常不需要像 C 一样显式写变量类型。
- C 通常被称为静态类型语言。
- Python 通常被称为动态类型语言。
- 当前阶段不要只背术语，要理解“类型告诉编译器如何理解和处理这份数据”。

13. 已经理解多个指针可以指向同一个变量，例如：
   `int *p1 = &age;`
   `int *p2 = &age;`

已经建立的核心直觉：
    age    → age 中保存的值
    &age   → age 的地址
    ptr    → ptr 中保存的地址

【二十六、2026-09-28 最新学习进度】
本次继续学习并已确认“完全理解”的内容：

一、sizeof 与指针类型
- sizeof 用于查看类型或对象占用多少 byte。
- sizeof 的结果类型是 size_t，printf 推荐使用 %zu。
- 指针本身占用空间；指针大小与指向的数据类型大小不是一回事。
- 在当前 64 位环境中，指针通常为 8 bytes，但不能把它当成 C 标准的绝对规则。

二、指针类型的重要性
- 指针保存地址。
- 指针类型告诉 C 这个地址所指向的对象应按什么类型理解和访问。
- *p 是通过地址访问所指向对象。
- 英文：A pointer stores an address, and its type tells C what kind of object is located at that address.

三、指针运算
- p + 1 不是简单的“地址 + 1 byte”。
- 指针运算按照指针所指向类型的大小进行缩放。
- int *：+1 移动一个 int；double *：+1 移动一个 double；char *：+1 移动一个 char。
- 英文：Pointer arithmetic is scaled by the size of the pointed-to type.
- *(p + 1) 表示访问下一个相同类型的对象。

四、数组基础
- array（数组）是一组连续存储的同类型对象。
- 英文：An array is a contiguous sequence of objects of the same type.
- int numbers[4] 表示包含 4 个 int 元素的数组。
- C 数组下标从 0 开始。
- numbers[0]、numbers[1]、numbers[2]、numbers[3] 访问四个元素。

五、数组与指针的关系
- 数组不是指针。
- 在很多表达式中，数组名会发生 array-to-pointer conversion（数组到指针的转换），转换为指向第一个元素的指针。
- int *p = numbers; 在这里可理解为 int *p = &numbers[0];
- 但 sizeof(numbers) 是重要例外：此时不会把数组转换成指针，而是计算整个数组的大小。
- 例如 4 个 int 且 sizeof(int)=4 时，sizeof(numbers)=16，而 sizeof(p) 在当前 64 位环境通常为 8。

六、数组下标与指针运算
- a[b] 等价于 *(a + b)。
- numbers[2] 与 *(numbers + 2) 访问同一个元素。
- 数组元素连续存储，因此指针运算可以沿数组元素移动。

七、数组长度
- 对数组对象，可用 sizeof(numbers) / sizeof(numbers[0]) 计算元素数量。
- 这依赖于当前表达式中的 numbers 仍然是数组，而不是已经转换为指针。

【三十、2026-09-29 最新学习进度】
本次继续学习，并已确认以下内容“理解/掌握”。不需要重复上述内容。

一、指针下标与数组下标的本质
- 已理解：p[i] 本质上等价于 *(p + i)。
- 因此，[] 并不是数组专属语法；指针也可以使用下标运算符。
- 例如：
  p[0] == *(p + 0)
  p[1] == *(p + 1)
  p[2] == *(p + 2)
- 已理解 a[i]、p[i]、*(a + i)、*(p + i) 在指向同一数组时可以访问同一个元素。
- 正式英文术语：
  subscript operator（下标运算符）
  pointer arithmetic（指针运算）
  dereference（解引用）
- 核心英文直觉：Array indexing is based on pointer arithmetic and dereference.

二、数组边界（array bounds）与越界访问
- 已理解：如果 int a[4]，合法下标是 0、1、2、3。
- a[4] 等价于 *(a + 4)，访问的位置已经不是数组中有效的元素。
- 正式术语：out-of-bounds access（越界访问）。
- C 通常不会像 Python 一样在普通数组下标操作时自动抛出 IndexError。
- 越界访问会进入 undefined behavior（未定义行为，UB），因此不能依赖其输出结果。
- 典型范围条件：如果数组长度为 n，则合法下标满足 0 <= i < n。

三、Undefined Behavior（UB）
- 已理解 undefined behavior（未定义行为）的基本含义：C 标准没有规定程序在该情况下必须产生什么结果。
- 越界访问是一个典型例子。
- UB 的实际表现可能不同：输出看似正常的值、输出其他值、程序异常、程序崩溃等，都不能作为“正确结果”理解。
- 当前阶段重点是建立“越界 = 不再有标准保证”的意识，不深入漏洞利用或底层安全细节。

四、Buffer Overflow 与 Off-by-one Error
- 已接触并理解 buffer overflow（缓冲区溢出）的基本概念：数据超出缓冲区原有边界，可能覆盖后续内存中的其他内容。
- 已理解 off-by-one error（差一错误），例如数组长度为 5 时把循环条件误写成 i <= 5，而正确条件通常是 i < 5。
- 核心习惯：看到数组访问/循环时主动检查边界条件。

五、NULL 指针
- 已理解 null pointer（空指针）的基本含义：指针当前不指向任何有效对象或函数。
- 例如：
  int *p = NULL;
- NULL 应理解为一个特殊的空指针值；初学阶段不要简单死记成“NULL 就是普通整数 0”，重点掌握其指针语义。
- 已区分以下三种情况：
  1. 有效指针：int age = 20; int *p = &age;
  2. 空指针：int *p = NULL;
  3. 未初始化指针：int *p;（其中保存的值不确定）
- 已理解：不能对 NULL 指针进行解引用，例如不要写 *p 来访问对象，因为它没有指向有效对象。
- 已接触 uninitialized pointer（未初始化指针）和 null pointer（空指针）的区别。
- Python 对照：C 的 NULL 与 Python 的 None 在语义上有一定帮助理解的相似性，但两者底层机制并不相同。

六、动态内存分配
- 已开始理解 dynamic memory allocation（动态内存分配）。
- 与固定数组相比，动态内存允许程序在运行过程中根据实际需求决定申请多大的内存。
- 固定数组示例：
  int a[10];
  大小在声明时已经确定。
- 动态内存的基本流程：
  程序运行
      ↓
  确定实际需要的空间
      ↓
  malloc 申请内存
      ↓
  得到起始地址
      ↓
  通过指针访问
      ↓
  使用完成
      ↓
  free 释放

七、malloc
- 已接触 malloc（memory allocation，内存分配）。
- malloc 的参数表示需要申请的 byte 数量，例如：
  malloc(100)
  表示申请 100 bytes 的内存。
- 如果希望申请能够容纳 5 个 int 的空间，写成：
  int *p = malloc(5 * sizeof(int));
- 这里 5 * sizeof(int) 表示“5 个 int 所需的总字节数”，而不是简单的 5 bytes。
- 已建立的直觉：malloc 申请成功后会返回这块动态内存的起始地址，由指针保存这个地址。
- 已接触 malloc 失败时需要检查返回值：
  if (p == NULL)
  {
      // 分配失败
  }
- 当前还没有深入学习 malloc 返回类型 void * 的标准语义、隐式转换，以及不同 C/C++ 写法的区别；这些留到下一节。

八、free
- 已理解 free 的基本作用：释放之前动态分配的内存。
- 基本流程：malloc → 使用 → free。
- 例如：
  int *p = malloc(5 * sizeof(int));
  ...
  free(p);
- 已理解：动态内存不会因为“指针变量本身离开作用域/被覆盖”就自动按照 Python 的方式被可靠地回收；程序员需要管理动态内存的释放。

九、Memory Leak
- 已接触 memory leak（内存泄漏）。
- 直觉模型：申请了动态内存，但丢失了能够找到它的指针或忘记 free，导致这块内存仍被占用却无法正常使用/释放。
- 因此 C 中“申请了资源，就要考虑释放”是非常重要的习惯。

【三十五、2026-10-04 最新学习进度：void *、calloc、realloc】
本次继续学习，并已确认以下内容“理解/掌握”。不需要下次重新讲这些基础内容。

一、malloc 为什么返回 void *
- 已理解：malloc() 的职责是申请一块指定大小的动态存储空间，它不需要知道调用者最终想把这块内存当成什么类型来使用。
- malloc() 的返回类型是 void *，可以理解为 generic object pointer（通用对象指针）。
- void * 可以保存对象的地址，但不指定所指向对象的具体类型。
- 英文直觉：A void * carries an address without specifying the pointed-to object type.

二、void * 与 typed pointer
- 已理解：int *、double *、char * 等属于 typed pointer（有类型的指针）。
- 指针类型不仅与“保存地址”有关，还告诉 C 应该如何理解和访问该地址对应的对象。
- void * 本身不提供具体对象类型信息，因此不能像具体类型指针那样直接按某种对象类型进行解引用。
- 例如：
  int age = 20;
  void *vp = &age;
  int *p = vp;
  printf("%d\\n", *p);
- 已理解：在标准 C 中，void * 可以隐式转换为其他对象指针类型，因此通常不需要给 malloc() 强制类型转换。
- 推荐写法：
  int *p = malloc(5 * sizeof(int));
- 初学阶段不推荐写成：
  int *p = (int *)malloc(5 * sizeof(int));

三、动态内存与指针类型的分工
- 已建立清晰区分：malloc/calloc 主要负责“申请多少存储空间”；typed pointer 负责“之后按什么类型访问这块空间”。
- 已理解：动态分配得到的存储空间本身不会因为 malloc() 被调用就自动带有 int/double 等高级类型标签。
- 典型理解：
  malloc(5 * sizeof(int))
      ↓
  申请足够存放 5 个 int 的存储
      ↓
  int *p
      ↓
  通过 int * 按 int 对象方式访问
- 英文直觉：Allocation determines how much storage you need; the pointer type determines how you access it.

四、calloc
- 已理解：calloc() 用于动态内存分配，并将分配的存储初始化为 all bits zero（全 0 bits）。
- 函数形式：
  calloc(number_of_elements, size_of_each_element)
- 例如：
  int *p = calloc(5, sizeof(int));
- 与 malloc(5 * sizeof(int)) 相比，calloc() 直接把“元素个数”和“每个元素大小”作为两个参数表达，并提供全 0 bits 初始化。
- 对通常的 int 使用场景，可以建立直觉：calloc(5, sizeof(int)) 后的 5 个 int 位置初始为 0。
- 已理解：calloc() 不是严格意义上的“创建数组”；更准确地说，是分配一块适合存放多个连续对象的动态存储空间，随后可以通过对应类型指针访问它。
- 英文术语：calloc = contiguous allocation；也可从功能上理解为 allocate + zero-initialize storage。

五、realloc
- 已理解：realloc() 用于调整一块已经动态分配的内存大小，可以扩大，也可以缩小。
- 示例：
  int *p = malloc(3 * sizeof(int));
  int *temp = realloc(p, 6 * sizeof(int));
- 已理解：realloc() 调整大小后，原有数据在适用范围内会被保留；新增空间不会自动像 calloc() 一样初始化为 0。
- 已理解：realloc() 之后，新的地址可能与旧地址相同，也可能不同。
- 当原地址后面没有足够连续空间时，内存分配器可能找到另一块更大的空间，把原数据移动过去，并释放旧区域。
- 因此不能假设 realloc() 一定“原地扩容”。
- 英文直觉：realloc() resizes an existing allocation; the resulting address may or may not change.

六、为什么推荐临时指针接收 realloc
- 已理解：不推荐在学习阶段直接无条件写：
  p = realloc(p, new_size);
- 更安全的常见模式是：
  int *temp = realloc(p, new_size);
  if (temp != NULL)
  {
      p = temp;
  }
- 原因：如果 realloc() 失败并返回 NULL，原来的 p 仍然需要保留，这样原来的动态内存仍可通过 p 管理和释放。
- 如果直接把返回值覆盖到 p，分配失败时可能丢失原来的地址，从而造成 memory leak（内存泄漏）风险。
- 已建立重要习惯：动态内存分配/调整都不能默认一定成功，要检查返回值。

七、malloc、calloc、realloc、free 的统一模型
- malloc：allocate（分配）指定字节数的动态内存。
- calloc：allocate + initialize storage to all bits zero（分配并将存储初始化为全 0 bits）。
- realloc：resize（调整已有动态内存的大小）。
- free：release（释放动态内存）。
- 当前已形成统一流程：
  allocation
      ↓
  malloc / calloc
      ↓
  typed pointer
      ↓
  access / use
      ↓
  realloc（必要时调整大小）
      ↓
  free

八、动态数组的雏形

- 例如可以从 3 个元素扩展到 6 个元素，再继续扩展。

【三十七、2026-10-06 最新学习进度：dangling pointer、use-after-free、alias、ownership、memory leak、double free】
本次继续学习，并已确认以下内容“理解/掌握”。下次不要重复这些内容。

一、free(p) 之后的核心理解
- 已理解：free(p) 释放的是 p 所指向的动态存储/对象，而不是删除指针变量 p 本身。
- free(p) 之后，指针变量 p 可能仍然保存原来的地址；它不会自动变成 NULL。
- 原来的动态对象生命周期已经结束，p 如果仍保存旧地址，就进入 dangling pointer（悬空指针）状态。
- 重要区分：指针变量的生命周期 与 它所指向对象的生命周期不是一回事。
- 英文直觉：free(p) ends the lifetime of the dynamically allocated object; it does not destroy the pointer variable itself.

二、dangling pointer（悬空指针）
- 已理解：dangling pointer 是仍保存旧地址、但原来所指向对象已经结束生命周期的指针。
- 英文：A dangling pointer is a pointer whose referenced object has already ceased to exist.
- 已理解：free 后即使原内存中的比特暂时还保留，也不能认为原 C 对象仍然存在。
- “内存中的比特还在那里”不等于“那个 C 对象仍然有效”。

三、use-after-free（释放后使用）
- 已理解：free(p) 后再通过 *p、p[i] 等方式访问原对象属于 use-after-free。
- 已理解：use-after-free 是错误的内存访问，可能导致 undefined behavior（未定义行为，UB）。
- 不能因为某次运行恰好打印出原值，就认为程序正确。
- 英文：Use-after-free means accessing an object after its lifetime has ended.

四、free(p); p = NULL;
- 已理解：常见安全习惯是：
  free(p);
  p = NULL;
- free(p) 负责结束动态对象的生命周期；p = NULL 负责修改指针变量本身，使其不再保存旧地址。
- NULL pointer 与 dangling pointer 已明确区分：
  NULL pointer：指针明确不指向有效对象；
  dangling pointer：指针仍保存旧地址，但对应对象已经失效。
- 已理解：free(p); p = NULL; 不能让已释放对象“复活”，只是清理该指针变量的状态。

五、多个指针指向同一个动态对象：alias（别名）
- 已理解：
  int *p2 = p1;
  复制的是 pointer value（指针值/地址值），不是把 p1 指向的对象复制一份。
- 因此多个 pointer 可以成为同一个对象的 alias（别名）：
  p1 ─────► [100] ◄───── p2
- `p2 = p1` 与 `x = *p1` 的概念不同：前者复制指针值，后者读取被指向对象的值。
- 英文：Different pointers can be aliases for the same object.

六、一个对象被 free 后，所有 alias 都需要重新考虑
- 已理解：如果 p1 和 p2 指向同一个动态对象，那么 free(p1) 会结束“那个对象”的生命周期；不是只让 p1 失效。
- free(p1) 后，p2 如果仍保存旧地址，也成为 dangling pointer。
- p1 = NULL 只修改 p1，不会自动修改 p2，也不会恢复已经释放的对象。
- 英文：Freeing an object invalidates all pointer aliases that still refer to that object.

七、ownership（所有权）与释放责任
- 已开始建立 ownership（所有权）意识：需要明确谁负责动态对象的生命周期，以及最终谁负责 free。
- 已理解：C 语言不会自动替程序员记录“谁是 owner、谁只是 alias/borrower”；这通常需要程序设计时明确约定。
- 重要思维：看到 malloc，不只想到“有了一个指针”，还要想到“谁负责管理并最终释放这块动态资源”。
- 英文：Ownership means knowing which part of the program is responsible for managing and eventually freeing an object.

八、double free（重复释放）
- 已理解：同一动态对象被尝试 free 两次是 double free。
- 例如 p1 和 p2 指向同一对象时：
  free(p1);
  free(p2);   // 错误
- 原因：第一次 free 已结束对象生命周期，第二次又尝试释放同一对象。
- 已理解：double free 属于严重的内存管理错误，并可能导致 undefined behavior。
- 特别区分：free(已经释放对象的旧地址) 与 free(NULL) 不一样；free(NULL) 是允许的。

九、memory leak（内存泄漏）
- 已理解：成功 malloc 后没有最终 free，可能导致 memory leak。
- 更深一层的理解：如果动态内存失去了可达的管理路径，例如把唯一的指针覆盖或设为 NULL，却没有先 free，那么内存仍被占用但程序已经无法正常找到它并释放。
- 示例思路：
  int *p = malloc(sizeof(int));
  p = malloc(sizeof(int));
  第一次 malloc 得到的内存失去地址后产生泄漏风险。
- 英文：A memory leak occurs when dynamically allocated memory is no longer reachable but has not been freed.

十、动态对象与局部指针变量的区别
- 已理解：局部指针变量离开作用域，不等于它所指向的 malloc 动态内存自动释放。
- 例如函数结束时局部 `p` 消失，但如果没有 free，由 malloc 得到的动态存储仍可能占用资源，从而形成 memory leak。
- 重要区分：pointer variable 的生命周期 与 dynamically allocated object's lifetime 不同。

十一、函数参数与指针的进一步联系
- 已理解：C 仍然是 pass by value（值传递）。函数参数 `int *p` 接收到的是调用者指针值的一份副本。
- 因此函数中的：
  p = NULL;
  不能直接让调用者外部的指针变量变成 NULL。
- 但函数中的：
  *p = 100;
  可以修改调用者所指向的同一个对象。
- 这为下一阶段 `pointer to pointer`（指向指针的指针）做准备。

十二、本次建立的统一内存生命周期模型
  malloc()
      ↓
  动态对象存在
      ↓
  pointer / alias 访问和使用
      ↓
  明确 ownership / 释放责任
      ↓
  free()
      ↓
  对象生命周期结束
      ↓
  旧地址不能再用于访问该对象
- 三个典型错误可以统一理解为生命周期管理问题：
  Memory Leak → 应该释放却没有释放；
  Use-After-Free → 已经释放却继续使用；
  Double Free → 已经释放却再次释放。

一、已经讲解的基础关系
- 对于：
  `int x = 10;`
  `int *p = &x;`
  `int **pp = &p;`
  已建立指向关系：`pp → p → x`。
- `p` 的类型是 `int *`，保存 `x` 的地址。
- `*p` 的类型是 `int`，访问 `x`。
- `pp` 的类型是 `int **`，保存指针变量 `p` 的地址。
- `*pp` 的类型是 `int *`，访问 `p`，得到 `x` 的地址。
- `**pp` 的类型是 `int`，通过两层解引用访问 `x`。
- 英文术语：pointer to pointer、dereference、pointer value、indirection。
- 英文直觉：A pointer to pointer stores the address of another pointer.

二、C 的值传递与修改调用者的指针
- 已讲解：C 使用 pass by value（值传递）；普通参数 `int *p` 接收调用者指针值的副本。
- 在函数里写 `p = NULL;` 只会修改局部指针参数，不会直接修改调用者的指针变量。
- 如果要访问调用者的指针变量本身，可以传入它的地址，例如 `f(&p)`，并用 `int **pp` 接收。
- `*pp = NULL;` 修改调用者的指针变量。
- `**pp = 100;`（前提是指针链指向有效的 `int` 对象）修改该整数对象。
- 重要直觉：`int **` 不会改变 C 的值传递规则；它让函数通过地址访问调用者的指针变量。
- English intuition: C passes pointer values by value. A pointer to pointer lets a function access the caller's pointer variable through its address.

三、`int **` 用于分配内存并把地址交给调用者
- 已讲解函数输出参数（output parameter）的用途：让函数通过 `int **out` 将新地址写入调用者的 `int *` 变量。
- 调用形式：`create_number(&p);`
- 函数内的 `*out = new_p;` 会修改调用者的 `p`，使它保存新分配的地址。
- `out = new_p;` 的含义不同：这只是给局部参数 `out` 赋值，不会将新地址写入调用者的指针变量；而且两边类型也不匹配。
- 已接触完整示例的关键步骤：
  1. 检查 `out == NULL`；
  2. 使用 `int *new_p = malloc(sizeof *new_p);` 申请内存；
  3. 检查 `new_p == NULL`；
  4. 用 `*new_p = 42;` 初始化；
  5. 用 `*out = new_p;` 把地址交给调用者；
  6. 调用者使用完后 `free(p);`，并可将 `p = NULL;`。
- `sizeof *new_p` 在此计算一个 `int` 对象所需的大小，与 `sizeof(int)` 相同；它不会读取 `new_p` 指向的内容来完成大小计算。
- 该模式展示了 malloc、指针、输出参数和 free 的组合。

四、函数返回 `int *` 与使用 `int **` 的区别
- 已说明：不是所有在函数中使用 `malloc()` 的场景都必须用 `int **`。
- 函数也可以直接返回 `int *`，把地址作为返回值；返回值可用于传递地址，而单独的状态码可能需要另外设计。
- 使用 `int **out` 的一种常见设计是：函数返回 `int` 表示成功/失败，同时通过输出参数传回地址。
- 下次还需要继续确认两种接口设计的取舍、错误处理方式，以及资源释放责任（ownership）。

五、Python 对照
- Python 中函数参数重新绑定（例如局部参数重新赋值为 `None`）不会自动重新绑定调用者的名称。
- 这个类比有助于理解函数局部参数与调用者变量的区别，但 Python 的名称绑定/对象模型不等同于 C 的指针和地址模型。

12. 多个资源同时申请时的清理路径；适时学习集中清理（cleanup）模式，理解 `goto cleanup` 在 C 中用于统一释放资源的常见用法及适用边界。
